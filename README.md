# took(툭) — 로우파이 와이어프레임 (기능 검증 단계)

AI 기반 개인 맞춤형 뷰티 서비스 took(툭)의 **구조·흐름·기능 검증용** 웹앱입니다.
디자인 단계가 아니므로 화면은 흰 배경·검은 글자·회색 테두리만 사용합니다. 단, 립 컬러 매핑의 영상·입술 매핑·프리셋 색상은 항상 실제 컬러로 표시합니다.

프로젝트 규칙(디자인·개발·데이터 원칙, 작업 방식)은 [CLAUDE.md](CLAUDE.md) 에 있습니다.

## 실행 방법
```bash
npm install        # MediaPipe 설치 + public/vendor 로 복사 + 얼굴 랜드마크 모델 다운로드(postinstall)
npm start          # http://localhost:3000
npm test           # 단위 테스트 (색상 계산 / 추천 / 바코드 / 챗봇)
npm run e2e        # Playwright 전체 흐름 테스트 (가짜 카메라 사용)
npm run build:static   # 서버 없이 동작하는 정적 버전 → dist/static (claude.ai Artifact 용)
npm run build:web      # 같은 정적 버전을 Vercel 등 일반 정적 호스팅용으로 (문서 골격 유지)
npm run e2e:static     # 정적 버전으로 같은 흐름 테스트
```

### 정적 버전 (claude.ai Artifact 링크)
`dist/static` 은 서버 API 없이 같은 `src/lib` 모듈(검색·추천·챗봇)을 브라우저에서 실행합니다.
페이지 간 전달값은 URL 쿼리 대신 sessionStorage 로 넘깁니다(`common.js` 의 `go()` / `qs()`).
- 얼굴 모델(.task)은 Artifact 가 제공하지 않는 형식이라 base64 텍스트(`face_landmarker.task.b64.txt`)로 포함합니다.
- Artifact 페이지에서는 카메라 사용이 허용되지 않습니다. 카메라 버튼을 누르면 권한 거부 안내가 표시되며, 샘플 그림이나 사진 업로드로 체험할 수 있습니다.
- Node 18 이상 필요 (런타임 의존성 없이 내장 `http` 사용)

### Vercel 배포 (정적 버전, 서버 없음)
```bash
npm run build:web
vercel deploy dist/static --temporary --yes   # 로그인 없이 임시 배포 (60분 뒤 만료, 출력되는 claim 링크로 계정에 가져가면 유지)
```
- 로그인했다면 `vercel deploy dist/static --prod` 로 계정의 프로젝트에 배포한다
- GitHub 저장소를 Vercel 프로젝트에 연결하면 `main` 에 push 할 때마다 자동 배포된다. 빌드 설정은 `vercel.json` (설치 `npm install` → 빌드 `npm run build:web` → 결과 `dist/static`)
- 휴대폰 QR 연결은 서버가 필요해 정적 버전에서는 안내 문구만 나온다. 나머지(카메라·챗봇·추천·바코드 카메라/번호 입력·팔레트)는 동작

### Render 배포 (고정 https 주소)
1. GitHub 에 저장소를 만들고 이 프로젝트를 올린다 (`git remote add origin <주소>` → `git push -u origin main`)
2. https://render.com 에 GitHub 계정으로 가입 → **New → Blueprint** → 저장소 선택 → `render.yaml` 대로 만들어짐 → **Apply**
3. 빌드(`npm ci`, 약 3~5분)가 끝나면 `https://took-○○○.onrender.com` 으로 접속
- 코드를 GitHub 에 push 하면 자동으로 다시 배포된다
- 무료 플랜은 15분 동안 접속이 없으면 잠들고, 다시 접속하면 30초쯤 걸린다. 휴대폰 QR 연결 정보는 메모리에 있어 깨어나면 새 QR 이 자동으로 만들어진다
- 공개 저장소·공개 사이트이므로 올리브영 수집 데이터와 상품 이미지가 외부에 공개된다는 점에 유의

### 인터넷 공개 주소로 실행 (휴대폰 QR 연결용, cloudflared 빠른 터널)
와이파이·방화벽과 상관없이 휴대폰에서 접속하려면 무료 터널로 임시 https 주소를 붙인다.
```bash
winget install --id Cloudflare.cloudflared   # 처음 한 번
npm start
cloudflared tunnel --url http://localhost:3000   # 출력되는 https://○○○.trycloudflare.com 으로 접속
```
- PC 에서 공개 주소로 챗봇을 열면 QR 에도 공개 주소가 자동으로 들어간다 (X-Forwarded-Host/Proto 반영)
- 터널을 켤 때마다 주소가 바뀌고, 켜져 있는 동안은 주소를 아는 누구나 접속할 수 있다 (민감 정보 없음)

### NFC 태그 인식 테스트 (갤럭시 S24, 직원용 `nfc-test.html`, 상단 메뉴 'NFC 테스트')
- **방법 A (서버 없이, 지금 바로)**: S24 Chrome 에서 `https://took-sieunkirns-projects.vercel.app/nfc-test.html` → "이 기기로 NFC 읽기 시작" → 카드를 뒷면에 대기
- **방법 B (PC·iPad 화면 + S24 리더기)**: `npm start` + `cloudflared tunnel --url http://localhost:3000` → PC 에서 터널 https 주소의 `nfc-test.html` → "휴대폰 연결 QR 띄우기" → S24 Chrome 으로 QR 열기(`nfc-phone.html`) → "NFC 읽기 시작". 휴대폰이 읽은 결과가 0.6초 폴링으로 PC 오른쪽 패널에 뜬다
  - http(LAN IP) 주소에서는 휴대폰 Web NFC 가 막힌다 (https 필요)
- Web NFC 는 NDEF 태그만 읽는다. 티머니·캐시비 같은 교통카드는 "감지됐지만 읽지 못함"으로 나오는 것이 정상이다. 출입카드는 종류에 따라 다르다(125kHz 는 감지 안 됨)
- 매핑 테이블: `public/js/nfc-test.js` 의 `NFC_TEST_MAP` (TOOK-001~003 → 테스트 립스틱 A~C, 가상 데이터). NDEF text/url 레코드에 `TOOK-001` 을 써 둔 스티커가 바로 맞춰진다. 번호만 읽히는 카드는 화면의 '임시 연결'(메모리만)로 시험한다
- 카드 번호는 저장하지 않고, 휴대폰 → PC 로는 가린 번호와 SHA-256 지문만 보낸다 (서버는 `sanitizeNfcReading` 으로 그 모양만 받는다)

### iPad(가로 화면)에서 실행
1. PC 에서 `npm run cert` (openssl 로 자체 서명 인증서 생성, PC 의 IP 포함) → `npm start`
2. 콘솔에 표시되는 `https://<PC IP>:3000` 을 같은 Wi-Fi 의 iPad Safari 에서 열기
3. "연결이 비공개로 설정되어 있지 않습니다" 경고 → 세부사항 보기 → 이 웹 사이트 방문
4. iPad 를 가로로 두고 사용 (홈 화면에 추가하면 주소창 없이 더 넓게 표시)
- iPad Safari 는 **HTTPS 에서만 카메라를 허용**합니다. http 로 접속해도 샘플 그림/사진 체험, 바코드, 챗봇은 모두 동작합니다.
- 자체 서명 인증서에서 카메라가 막히는 경우 ngrok / cloudflared 같은 HTTPS 터널 주소로 접속하세요.
- 실제 iPad 기기 테스트는 하지 않았고, Chromium 에서 iPad 가로 화면 크기로 레이아웃을 검증했습니다.
- 제품 데이터 재생성: `npm run seed` (가상 데이터, color_lab, EAN-13 체크 디지트 자동 계산)
- 올리브영 데이터 다시 변환: `npm run import:oliveyoung [크롤링 JSON 경로]` (기본 `../크롤링c/oliveyoung_lip_tints.json`). 크롤링 폴더에 받아 둔 이미지 파일도 `public/images/lip-tints` 로 다시 복사한다

올리브영 데이터 변환 규칙 (`scripts/import-oliveyoung.js`, 수집하지 않은 정보는 지어내지 않음)

- 가격: 판매가(`price`), 정가(`list_price`) / `url`: 올리브영 상세 페이지 (화면에 "올리브영에서 보기" 링크)
- 대표 색상값 → `color_lab` 계산, 색상 계열은 가장 가까운 기준 색으로 **추정** (`color_family_source: estimated_from_color`, 화면에 "색상값으로 추정")
- 제형은 상품명 단어(벨벳·매트·블러·글로우 등)로 **추정** (`finish_source: product_name`), 단서가 없으면 `null` → "정보 없음"
- 바코드·색상명·설명은 수집되지 않아 비움. 바코드 인식은 "등록되지 않은 제품"으로 안내하고, 시연은 가상 데이터로
- 대표 이미지: 크롤링 폴더에 받아 둔 이미지 파일(`image_path`)을 `public/images/lip-tints` 로 복사해 그 파일을 쓴다(현재 285개 전부, 약 16MB). 파일이 없으면 크롤링 데이터의 `src`·`image_url` 이나 `oliveyoung_image_manifest.json` 의 올리브영 이미지 서버(https://image.oliveyoung.co.kr) 주소를 쓰고, 주소는 추측하지 않는다. 카드 맨 위 같은 크기의 자리에 표시하고, 불러오지 못하면 "이미지 준비 중" 자리로 표시. 가격: 크롤링c 에는 할인가가 없어 정가를 가격으로 쓴다
- 수집 데이터이므로 외부 공개(터널·배포) 시 이용 조건에 유의

## 기존 프로젝트 분석 결과
작업 디렉터리가 비어 있었고, 연결된 GitHub 저장소에도 took 관련 프로젝트가 없었습니다. 따라서 새로 구성했습니다.
기술 스택은 Node 내장 서버, 순수 HTML/ES 모듈, MediaPipe Tasks Vision(로컬 제공)입니다.

## API
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/products?finish=` | 전체 제품 |
| GET | `/api/products/:id` | 제품 상세 (없으면 404) |
| GET | `/api/products/barcode/:code` | 바코드 검색 → `{found, product}` (형식 오류 400) |
| GET | `/api/recommend?hex=&finish=&limit=&exclude=` | 색차(ΔE2000) 오름차순 추천 |
| POST | `/api/chat` `{message, baseProductId?, selectedHex?}` | 규칙 기반 응답 + 제품 목록 |

## 합본 화면 (`studio.html`, 상단 탭 '합본')
왼쪽에는 립 매핑 카메라가 항상 켜져 있고, 오른쪽 탭에서 **색 조제 · 챗봇 · 추천 · 바코드**를 한 화면에서 쓴다.
- 색 조제: 어울리는 컬러 추천, 프리셋, 색상·채도·밝기 슬라이더로 직접 조제, 텍스처·농도, '이 컬러로 제품 추천 받기'
- 챗봇: AI 뷰티 챗봇과 같은 대화(음성·읽어주기·비교함). 립 매핑에서 고른 색을 기준 색으로 쓴다
- 대표 이미지가 있는 제품만으로 추천하는 API 옵션: `/api/chat` 의 `imageOnly`, `/api/recommend?image=1` (화면의 테스트 버튼은 없앰)
- 추천: 챗봇·추천 버튼으로 받은 제품 목록. 카드의 '입술에 발라보기'로 왼쪽 카메라 입술에 그 색을 바로 입힘
- 바코드: 휴대폰 QR 연결·PC 카메라·사진·번호 입력. 인식한 제품 설명은 챗봇 탭에
- 구현: 립 매핑(`lip.js`)과 챗봇(`chat.js`)을 그대로 불러오고 창 이벤트(`took:color`, `took:recommend`, `took:apply`, `took:show-tab`)로 주고받는다

## 팔레트 (`palette.html`, 상단 탭 '팔레트', 테스트)
물감을 섞어 립 색을 조제하는 실험 화면 (`js/palette.js` + `js/lip.js`). 왼쪽은 립 매핑 카메라, 오른쪽 위는 조제한 색·레시피·텍스처·농도·추천, 오른쪽 아래는 팔레트.
- 물감: 립 컬러 매핑 탭에서 고를 수 있는 컬러 22가지(`lip-engine.js` 의 `PRESETS`). 물감을 누르면 한 방울이 포물선을 그리며 섞는 칸으로 날아가고, 끌어다 놓으면 놓은 자리에 떨어진다
- 떨어진 물감은 소용돌이 마블 줄무늬로 퍼지고 바탕색이 새 혼합색으로 천천히 바뀐다. 섞는 칸을 드래그하면 저어진다
- 혼합색은 방울 수를 가중치로 OKLab 공간에서 평균한다. 레시피(물감별 방울 수)·한 방울 빼기
- 섞는 칸 색이 바뀌는 동안 같은 색이 카메라 입술에 바로 입혀진다(`took:apply` 이벤트, `quiet`). '초기화'는 팔레트를 비우고 입술 색을 기본 컬러(#C08A94 · 매트)로 되돌린다
- '이 색과 비슷한 제품 추천'을 누르면 오른쪽에 조제한 색과 추천 제품만 남는다(팔레트·텍스처·농도 숨김). 카드의 '입술에 발라보기'로 그 제품 색을 입히고, 오른쪽 위 '다시하기'로 초기화해 팔레트로 돌아간다
- 물감·섞는 칸·결과 색은 실제 색으로 표시한다 (립 컬러 조절의 색 표시)

## 홈 화면
무채색(검정·흰색·회색)만 쓰고 흰 카드·큰 글자로 꾸민 사용자용 첫 화면.
움직임(`js/home.js`): 처음에는 가운데에 제목만 크게 뜨고 글자가 하나씩 튀어 오른 뒤 제자리로 이동, 나머지는 여러 방향에서 날아든다(클릭·키 입력으로 건너뛰기, 상단 '홈' 버튼으로 오면 인트로 없이 바로 보여 준다). 배경은 커서를 피해 밀려나고 진해지는 회색 점 격자(누르면 물결), 제목 글자 들썩임, 커서 쪽으로 끌리는 버튼, 커서 방향으로 기우는 기능 카드, 스크롤하면 나타나는 아래 영역. 동작 줄이기 설정이면 움직이지 않는다.
소개 문구와 주요 버튼(립 발라 보기 / 챗봇에게 물어보기) → 기능 카드 2개(립 컬러 매핑·AI 뷰티 챗봇, 선 아이콘·설명. 바코드 검색은 챗봇으로 합침) → 이렇게 써 보세요(3단계) → 최근 기록(고른 색·측정한 톤·챗봇 기준 제품과 바로가기).

## 화면 비율 (iPad 가로 최적화)
가로 방향이고 너비가 960px 이상이면 립 컬러 매핑·챗봇·합본·팔레트 화면이 **스크롤 없이 한 화면**에 맞춰집니다.
- 립 컬러 매핑(`lip-together.html`): [가상 메이크업 화면(가장 넓게) | 어울리는 컬러·컬러·텍스처·농도·추천] 2열. 카메라는 화면에 들어오면 자동으로 켜짐. '이 컬러로 제품 추천 받기'를 누르면 카메라는 그대로 두고 오른쪽 패널이 제품 추천 목록으로 바뀜. 제품의 '입술에 발라보기'로 그 제품 색·제형(벨벳은 매트로 근사)을 바로 적용
- AI 뷰티 챗봇(사용자용, `chat.html`): 메신저형 대화창 하나. 마이크 아이콘(음성 질문)·입력창·보내기, 답변 읽어주기 스피커 아이콘, 새 대화, 기준 제품 표시(해제 가능). 추천 제품은 넓은 화면(가로 960px 이상)에서 오른쪽 '추천 제품' 패널에 고정(대화엔 짧은 번호 목록, "2번 자세히" 같은 답은 패널 카드 강조), 좁은 화면에서는 대화 안 카드. 카드에 번호·상세 보기·기준 제품으로·+ 비교. 답변마다 다음 질문 버튼
  - 바코드로 제품 알아보기: 오른쪽 패널(추천 목록이 없을 때 기본, '바코드로 찾기' 버튼으로 전환)에서 카메라로 바코드를 찍거나 번호를 입력하면 등록 제품을 조회해 챗봇이 대화로 설명하고 기준 제품으로 정함. 미등록 바코드는 지어내지 않고 안내. 좁은 화면은 입력줄의 바코드 아이콘으로 패널을 엶
    - 인식: ZXing(@zxing/library, npm install 시 public/vendor/zxing 로 복사, 외부 CDN 없음). 윈도우 크롬에 내장 BarcodeDetector 가 없어 사용. 0.08초마다 카메라 프레임(최대 1920×1080, 지원 시 연속 자동 초점)을 원본·살짝 흐림·가운데 확대·90° 회전·더 흐림 변형으로 돌아가며 읽음(public/js/barcode-scan.js). 웹캠처럼 잡음·흐림이 있는 영상 시험에서 원본만 읽을 때 18가지 중 1가지 → 8가지 중 7가지(1초 이내) 인식
    - 휴대폰으로 찍기(QR, 추천): PC 챗봇 패널에 QR 표시 → 휴대폰 기본 카메라로 QR 을 비추면 `scan-phone.html` 이 열림 → "바코드 사진 찍기"(휴대폰 기본 카메라 사진이라 HTTPS 불필요)로 찍으면 휴대폰에서 바코드를 읽어 번호만 서버로 보내고, PC 화면이 1초마다 서버에서 새 소식을 가져감(폴링) → PC 챗봇이 제품을 설명. 실시간 스트림(SSE)은 cloudflared 빠른 터널이 모아 두었다 늦게 보내서 쓰지 않음
      - 서버: `src/lib/pairing.js`(연결 정보는 메모리, 30분 미사용 시 삭제, 추측 어려운 16자리 연결 번호), API `POST /api/pair`, `GET /api/pair/:id/poll?after=`, `POST /api/pair/:id/hello`, `POST /api/pair/:id/code`
      - 조건: PC 와 휴대폰이 같은 와이파이. PC 를 localhost 로 열어도 QR 에는 PC 의 와이파이 주소(예: http://192.168.x.x:3000)가 들어감. 처음엔 윈도우 방화벽 허용이 필요할 수 있음. 정적 버전(서버 없음)에서는 사용 불가 안내
      - PC 에서도 '사진으로 찍기'로 사진 파일 속 바코드를 읽을 수 있음
    - 시연용 바코드: `barcodes.html` 에 등록 제품 27개의 EAN-13 바코드를 SVG 로 그림(public/js/ean13.js). 휴대폰에 띄우거나 인쇄해서 카메라에 비춰 테스트
  - 비교함: 카드의 '+ 비교'로 최대 3개를 입력창 위 비교함에 담고 '비교하기' → 대화에 비교표(계열·제형·가격·밝기·색상값)와 쉬운 말 요약. "1번이랑 2번 비교해 줘"도 같은 비교표
  - 말투: 사용자에게는 '데이트 · 글로시로 9개를 찾았어요'처럼 친근한 문장만 보여 주고, 기술적 조건(제형 = …, ΔE 등)은 응답의 conditions 로 따로 돌려 준다(화면에는 표시하지 않음)
  - 음성 질문·읽어주기는 public/js/voice.js (AI 뷰티 챗봇과 합본의 챗봇 탭이 같이 씀)
  - 음성 질문: 브라우저 Web Speech API(ko-KR, Chrome/Edge)로 말을 글자로 바꿔 같은 규칙 기반 챗봇에 보냄. 음성은 브라우저의 음성 인식 서비스로 전송됨
  - 인식 보정: 후보 문장 최대 5개 중 챗봇이 가장 많은 조건을 알아듣는 문장 선택 → src/lib/spoken.js 로 금액·비슷한 발음 보정(타이핑 오타에도 적용). 보정한 내용은 답변 앞에 안내
  - 대화 맥락: 서버가 돌려준 context(직전 조건·보여 준 제품 번호)를 다음 질문에 그대로 보내 "그중에 제일 싼 거", "두 번째 거 자세히/기준으로", "1번이랑 2번 비교", "더 보여 줘", "매트 말고", "글로시한 걸로 바꿔", "왜 추천했어"에 답함
  - 상황(데일리·면접·데이트·파티·여행·계절)·퍼스널 톤(웜/쿨, 4계절, 립 컬러 매핑 측정값)·입술 고민(건조·지속력 등)은 말하지 않은 계열/제형을 대신 정하는 추천 성향으로 쓰고, 맞는 제품이 없으면 그 성향은 뺌
  - 결과가 없으면 조건을 하나씩 빼 보고 결과가 생기는 조건을 안내. 답변마다 다음 질문 추천 버튼, 답변 준비 중 표시
  - 여전히 외부 AI 없이 규칙 기반이며, 화면 안내와 "너 AI야?" 답변에서 그렇게 밝힘
- 검증한 화면 크기: 1180×820(iPad 10세대/Air), 1180×740(Safari 표시 영역), 1194×834(Pro 11), 1366×1024(Pro 12.9), 1133×744(mini), 1080×740, 1024×768
- 버튼·입력창은 터치를 고려해 높이 44px 이상. 세로 화면이나 좁은 화면에서는 위에서 아래로 쌓입니다.

## 사용자 흐름
- **A** 홈 → 립 컬러 매핑 → 카메라 자동 시작 → (나에게 어울리는 컬러 추천: 눈 흰자 기준 조명 보정 → 볼·이마 피부색 Lab 색상각(웜/쿨) + 피부 밝기·눈썹 대비(밝은/깊은) → 4계절 톤 추정, 경계면 다음 후보 안내, 측정값 표시. 규칙 기반 참고용) → 컬러·텍스처·농도 선택 → 같은 화면 오른쪽에 추천 → 입술에 발라보기
- **B** 홈 → 챗봇 → 바코드(휴대폰 QR·PC 카메라·사진·번호 입력) → 제품 설명 → 기준 제품 조건 반영 추천
- **C** 홈 → 챗봇 → 질문 → 추천 → 상세 → 챗봇 복귀(대화 유지)

페이지 간 상태(선택 색상, 기준 제품, 대화, 마지막 바코드)는 `sessionStorage` 에 저장되고, URL 파라미터가 우선 적용됩니다.

## 추천·챗봇 규칙
- 유사도 = `max(0, 100 − 2 × ΔE2000)`. 무작위 요소는 없습니다.
- 챗봇이 이해하는 조건은 다음과 같습니다.
  - 제형: 글로시/매트/새틴/벨벳
  - 가격: 더 저렴한/비싼(기준 제품 대비), "2만원 이하"
  - 색상 계열: 레드·핑크·코랄·오렌지·누드·브라운·로즈·베리·플럼·버건디
  - 비슷한 색, 더 밝은/어두운 색(기준 색상 필요)
  - 브랜드명
  - 기준 제품 정보 질문: 가격/제형/바코드/설명
- 기준 색상의 우선순위는 기준 제품 → 립 컬러 매핑에서 선택한 색상 순입니다. 기준 색상이 없으면 색상 비교 결과를 지어내지 않고, 기준 색상이 없다고 안내합니다.

### 한국어 / 영어
홈 대기 화면과 상단 메뉴의 **🌐 Language** 로 바꾼다. 언어는 탭 저장소(`took.lang`)에 두어 자동 초기화 때 한국어로 돌아간다.
- 화면 문구: `public/js/i18n.js` 의 문구 표 (`data-i18n` 속성, `t('키')`). 홈·메뉴·팔레트·제품 상세·챗봇 화면·초기화 안내·음성 안내
- 제품 이름: 영어면 글로벌 올리브영 이름(`brand_en`·`name_en`), 링크도 글로벌 상세. 가격은 원화(₩)
- 챗봇: 영어로 물으면 `src/lib/chat-en.js` 가 알아듣고(한국어판과 같은 조건 모양) 엔진이 영어로 답한다. 영어로 답할 때는 **영어 이름이 있는 221개 안에서만** 추천한다(한국어 이름이 섞이지 않게, 이름을 지어내지 않게). 영어 이름이 없는 브랜드는 "등록되지 않은 브랜드"로 안내
- 음성: 영어면 인식 `en-US`, 읽어주기 영어 목소리
- 평가: `npm run eval:chat -- --lang en`

### 키오스크 자동 초기화
다음 손님에게 앞 손님의 대화·측정한 톤·고른 색이 보이지 않도록, **90초 동안 조작이 없으면** "계속 이용하시나요?" 안내를 띄우고
15초 안에 응답이 없으면 저장한 상태를 모두 지우고 홈으로 돌아갑니다 (`public/js/common.js` 의 `setupIdleReset`, 모든 화면 공통).
- '계속하기'나 안내 바깥을 누르면 그대로 이어서 씁니다. '처음으로'는 바로 초기화합니다.
- 읽어주기·음성 듣기 중에는 기다립니다(최대 60초). 홈에 지울 것이 없으면 아무것도 하지 않습니다.
- 기기마다 대기 시간을 바꾸려면 그 기기 브라우저 콘솔에서 `localStorage.setItem('took.idleSeconds', '120')` (10초 이상).
- 직원용 화면(`voice-test.html`, `barcodes.html`)은 `<body data-idle-reset="off">` 로 끕니다.
- 테스트 단계에는 상단 메뉴 오른쪽 끝 **자동 초기화 테스트** 버튼으로 안내를 바로 띄워 볼 수 있습니다. 배포 때는 `common.js` 의 `IDLE_TEST_BUTTON` 을 `false` 로.

### 음성 인식 정확도 측정 (`voice-test.html`, 테스트용·메뉴에 없음)
키오스크로 쓸 iPad 에서 `/voice-test.html` 을 열고 문장 40개를 차례로 읽으면, 챗봇과 같은 음성 인식·보정을 거쳐
글자 정확도(보정 전/후)와 뜻 일치(챗봇이 같은 조건으로 알아들었는지)를 기록합니다. **결과 내려받기**로 받은 JSON 을 보고
자주 틀리는 말을 `src/lib/aliases.js`(말소리 별칭: "romand" → 롬앤, "쓰리씨이" → 3CE)에 추가합니다.
- iPad 는 https 주소에서만 마이크가 열립니다 (배포 주소 또는 `npm run cert`).
- 결과는 그 기기의 브라우저에만 저장됩니다.

### LLM 보조 (선택, 서버 버전만)
`.env` 에 OpenAI 호환 주소를 넣으면(`.env.example` 참고) 규칙 챗봇이 **못 알아들은 말만** LLM 이 대신 답합니다 ("혈색 도는 거", "벽돌색"). 비워 두면 지금처럼 규칙만 씁니다.
- LLM 은 `src/lib/llm/tools.js` 의 검색 도구(규칙 챗봇과 같은 검색)만 부를 수 있고, 마지막 답은 `{intent, product_ids, say}` JSON 으로만 받습니다.
- 서버가 검사합니다: 제품 id 는 이번에 도구가 돌려준 것이어야 하고, `say` 에는 브랜드·가격을 쓸 수 없습니다. 제품 이름·제형·가격은 서버가 DB 에서 채웁니다.
- 검사에 실패하거나 LLM 이 오류·시간 초과면 규칙 챗봇 답을 그대로 씁니다. `/api/chat` 응답의 `engine` 이 `llm` / `rule-based` 로 어느 쪽이 답했는지 알려 줍니다.
- 정적 버전(Vercel)은 서버가 없어 규칙만 씁니다.
- 평가: `npm run eval:chat -- --provider hybrid` ([test/eval/README.md](test/eval/README.md))

## 거울 ver4 (`mirror-v4.html`, 상단 메뉴 '거울 ver4', 하프미러용)
- 거울(ver3, `mirror.html`)은 카메라 영상을 화면 전체에 채워 하프미러 뒤에서는 실제 반사상과 겹치고 밝은 화면 때문에 거울 효과가 사라집니다. ver4 는 "검은 부분 = 거울"을 이용해 화면 대부분을 `#000` 으로 두고 카메라 영상은 가로 중앙의 세로형 창(기본 높이 65dvh, 창 중심은 위에서 40%)에만 그립니다.
- 대기: 전체 검정(= 거울) 위에 흰 선만 — 왼쪽 위 TOOK 로고(흰색 SVG), 오른쪽 위 시계, 가운데 점선 얼굴(천천히 밝아졌다 어두워짐), 아래 '제품을 태그해보세요'. 홍보 사진은 직원 설정(끄기 기본 / 작게 / 전체). 체험: 창 안에 영상·입술 매핑, 독은 창 아래 검정 영역(배경 투명, 흰 글자·흰 버튼). 팔레트·비슷한 제품처럼 키가 큰 패널이 열리면 창이 0.3초 동안 줄어 독과 겹치지 않습니다. 가로 화면에서는 독이 창 오른쪽에 세로로 놓입니다.
- 직원 설정(`?setup=1` 또는 왼쪽 위 2초): ver3 항목 + 창 높이(40~90%)·창 세로 위치(20~60%)·창 테두리·대기 홍보 사진. 아래에 지금 창의 픽셀 크기·위치가 보여 거울 도착 후 실측 조정에 씁니다. 저장 키 `took.mirror4`(ver3 `took.mirror` 와 따로), 색 보정 행렬 `took.colorProfile` 은 공유.
- 코드는 `mirror.js` 를 `mirror-v4.js` 로 복제해 레이아웃(대기 사진·창 배치·설정 항목)만 바꿨습니다. 카메라·입술 매핑·팔레트·추천·NFC 는 같은 모듈(lip-view, lip-tracker, palette-mixer, lip-engine, nfc)을 씁니다. 스크린샷: `node scripts/shots-mirror-v4.mjs` → `screenshots/`
- 실제 하프미러·iPad·갤럭시탭 기기 테스트는 하지 않았고, Chromium 가짜 카메라로 태블릿 세로(820×1180, 800×1280)·가로(1280×900, 1280×800) 화면 크기에서 레이아웃을 검증했습니다.

## 아직 구현되지 않은 기능 / 제약
- **외부 AI API 기본 꺼짐**: 챗봇은 규칙 기반이며 화면에 그렇게 표시합니다. LLM 보조는 `.env` 를 채운 서버 버전에서만 켜지고, 아직 실제 모델로 평가하지 않았습니다(가짜 모델로 연결·검증 동작만 확인).
- **가상 립 컬러 미리보기**: 와이어프레임 원칙에 따라 선택 색의 명도(L*)에 해당하는 회색으로만 칠합니다. 디자인 단계에서는 `lip.js` 의 `renderMap()` fillStyle 만 바꾸면 됩니다.
- 입술 추적은 정면 얼굴 1명 기준입니다. 조명에 따라 '입술색 추출' 값이 달라질 수 있습니다.
- 제품은 시연용 가상 데이터 27개입니다. 실제 제품 DB나 이미지(`image_url`)는 아직 없습니다.
- 사용자 계정, 서버 측 영속 저장(장바구니·히스토리 등)은 구현하지 않았습니다.

## 실제 하드웨어/API 연결이 필요한 부분
- 바코드 스캐너: 키보드 입력(HID) 방식만 지원합니다. 입력창에 포커스가 있어야 하며, 연결 여부는 감지하지 않습니다. 카메라로 바코드를 인식하는 기능은 없습니다.
- 실제 카메라: e2e 테스트는 Chromium 가짜 카메라로 실행했습니다. 얼굴 추적은 샘플 그림 3종으로 검증했습니다.
- AI 챗봇: `/api/chat` 은 `hybridAnswer()` (규칙 먼저, 못 알아들은 말만 LLM)를 씁니다. LLM 주소·모델·키는 `.env` 로 넣습니다. 응답 형식 `{reply, products, context}` 는 규칙 챗봇과 같습니다.
