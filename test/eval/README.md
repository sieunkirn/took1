# 챗봇 평가 세트 (로드맵 0단계)

규칙 챗봇(`src/lib/chat.js`)과 나중에 붙일 LLM 층을 **같은 질문·같은 채점 기준**으로 비교하기 위한 한국어 평가 세트입니다.
정답(라벨)은 "규칙 챗봇이 지금 하는 답"이 아니라 **좋은 챗봇이라면 해야 할 답**입니다. 그래서 규칙 챗봇이 틀리는 문항이 일부러 들어 있고, 그 점수가 LLM 층이 넘어야 할 기준선입니다.

```bash
npm run eval:chat                 # 실제 데이터(올리브영 285개)로 규칙 챗봇 채점
npm run eval:chat -- --verbose    # 틀린 문항의 답변까지 출력
npm run eval:chat -- --only H     # 한 분류만 (문항 id 앞 글자)
npm run eval:chat -- --lang en    # 영어 챗봇을 영어 문항(chat-cases.en.json, 54개)으로 → results/rule.en.json
```
결과는 `test/eval/results/rule.json` 에 저장됩니다.

LLM 층(1단계)을 켠 뒤에는 같은 문항으로 하이브리드(규칙 먼저, 규칙이 못 알아들은 말만 LLM)를 채점합니다. `.env` 에 `LLM_BASE_URL`·`LLM_MODEL` 이 있어야 합니다 (`.env.example` 참고).
```bash
npm run eval:chat -- --provider hybrid           # → test/eval/results/hybrid.json, [LLM] 표시는 LLM 이 답한 턴
```

## 문항 형식 (`chat-cases.json`)
```json
{ "id": "E03", "cat": "이어지는 질문", "tone": null, "base": null,
  "turns": [
    { "say": "글로시한 립 추천해 줘", "expect": { "outcome": "products", "each": { "finish": "glossy" } } },
    { "say": "그중에 제일 싼 거는?", "expect": { "outcome": "products", "pick": "cheapest" } }
  ] }
```
- 여러 턴이면 앞 턴의 대화 상태(context)를 다음 턴에 넘깁니다.
- `base`: 바코드로 정한 기준 제품 id, `hex`: 립 컬러 매핑에서 고른 색, `tone`: 측정한 퍼스널 톤

### expect 항목
| 키 | 뜻 |
|---|---|
| `outcome` | 답의 종류. 배열이면 그중 하나면 통과. `products`(제품 목록) · `compare`(비교) · `set_base`(기준 제품 지정) · `no_match`(조건에 맞는 제품 없음을 알림) · `text`(제품 없이 말로 답함: 되묻기·안내·인사) · `not_understood`(못 알아들음) |
| `query` | 알아들은 검색 조건(`context.query`)에 이 값들이 들어 있어야 함. 배열은 "이 원소들을 포함" |
| `each` | 보여 준 제품이 모두 지켜야 할 조건: `finish`(배열이면 이 중 하나), `finishNot`, `families`(이 중 하나), `familiesNot`, `brand`, `maxPrice`, `minPrice` |
| `sort` | `price_asc` / `price_desc` |
| `pick` | 앞 턴 목록에서 골라야 할 제품: 순번(0부터, -1 은 마지막) 또는 `cheapest` / `priciest` |
| `replyHas` | 답변에 들어 있어야 할 말(이 중 하나) |

### 모든 문항에 항상 하는 근거 검사 (환각 검사)
- 보여 준 제품 id 가 모두 DB 에 있다
- 답변에 나온 브랜드가 모두 보여 준 제품·앞 턴 제품·기준 제품의 브랜드다 (DB 에 없는 브랜드를 말하면 실패)
- 답변에 나온 "N원" 이 모두 관련 제품 가격이거나 사용자가 말한 금액이다

근거 검사는 라벨과 상관없이 **0건이어야** 합니다. LLM 층의 출시 기준: 문항 통과율이 규칙 챗봇 이상, 근거 위반 0건.

## 기준선 (2026-11-04, 규칙 챗봇, 올리브영 285개)
전체 140/155 (90.3%) · 근거 위반 0건 · 평균 3ms.
H 자유 표현 11/20(55%), I 없는 제품·범위 밖 10/12, E 이어지는 질문 18/20, A 조건 검색 29/30, G 음성 오류 14/15, 나머지 분류는 모두 통과.

같은 날 규칙 빈틈 6개(가격 하한·가격대·"짜리", 열 번째, 이어 물을 때 브랜드 유지, 띄어 말한 브랜드, 등록되지 않은 브랜드 안내, "천 원")를 고친 뒤:
**전체 146/155 (94.2%) · 근거 위반 0건.** 남은 9개는 모두 H 자유 표현으로, LLM 층(1단계)이 넘어야 할 몫입니다.

표현 사전(느낌·색 이름·싫은 질감)과 잡담 받아 주기를 넣은 뒤, L·M 분류를 더해: **전체 176/176 · 근거 위반 0건.**
H 는 사전을 만들 때 본 문항이라 실제 실력보다 높게 나옵니다. 새 말투가 들어오면 M 처럼 따로 문항을 만들어 점검하세요.

## 분류 (id 앞 글자)
A 조건 검색 · B 상황 · C 퍼스널 톤 · D 입술 고민 · E 이어지는 질문 · F 기준 제품/색 · G 음성 인식 오류 · H 자유 표현 · I 없는 제품·범위 밖 · J 가벼운 대화 · K 주입·안전 · L 잡담·기분 · M 새 표현(검증용)

M 은 표현 사전을 만든 뒤, 사전을 만들 때 보지 않은 말로 따로 점검한 문항입니다 (첫 점검에서 "체리 같은 색", "한번에 다 비교해 줘" 2개가 틀려 고쳤습니다). H 는 사전을 만들 때 보고 맞춘 문항이라 H 점수는 실제보다 좋게 나옵니다.

H(자유 표현)는 규칙에 없는 말투로 같은 뜻을 묻는 문항이라 규칙 챗봇이 많이 틀리는 게 정상입니다.
