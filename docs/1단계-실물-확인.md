# 1단계: 실물 확인 순서표 (2026-11-20)

코드로는 확인할 수 없고, 실제 기기 앞에서 해야 하는 일만 모았다.
각 항목의 "결과 적는 곳"을 채워 주면 2단계(시연 안정화)에서 고칠 범위가 정해진다.

> 카메라 바코드 읽기는 2026-11-20 기능에서 뺐으므로 확인하지 않는다. 제품 올리기는 NFC 리더기 하나로 간다.

---

## 1. NFC 테스트 카드 1·3번 번호 (5분)
지금 1·3번 카드는 메모에 글자가 빠진 11자리 번호로 등록돼 있다(부분 일치로 겨우 인식).

1. 키오스크 시작 화면을 **5초 길게 눌러** 관리자 화면을 연다
2. **NFC 테스트**를 누르고 카드 1번 → 3번 순서로 리더기에 댄다
3. 화면에 크게 나온 **14글자 번호**를 그대로 적는다

| 카드 | 읽은 번호 (14글자) |
|---|---|
| 1번 | |
| 3번 | |

→ 번호를 알려 주면 `public/js/nfc.js` 의 `NFC_TAGS` 를 바꾼다.

## 2. APK 실제 기기 (15분)
코드 점검 결과: 페이지가 카메라를 요청하면 안드로이드 권한 창을 띄우고, 허락하면 WebView 에 넘겨주는 흐름은 맞게 짜여 있다. 실제 기기에서 한 바퀴만 돌려 보면 된다.

1. `npm run build:apk` → `dist/apk/took.apk` 를 기기에 설치 (새 아이콘: 검정 바탕 핑크 TOOK 마크)
2. 앱을 열고 화면을 눌러 거울로 들어간다 → **카메라 권한 창이 뜨는지**
3. 허락 → 얼굴에 **흰 괄호 4개가 따라오는지**, 입술에 색이 칠해지는지
4. 다이얼을 돌려 색이 바뀌는지 → 로고 버튼으로 추천 → 카드의 **가져가기** → QR 이 보이는지
5. 홈 버튼으로 나갔다가 다시 들어와도 카메라가 다시 켜지는지

| 확인 | 됨 / 안 됨 | 메모 |
|---|---|---|
| 권한 창 | | |
| 얼굴 괄호·입술 색 | | |
| 다이얼·추천·가져가기 | | |
| 나갔다 들어오기 | | |
| 기기 이름·안드로이드 버전 | | |

안 되는 게 있으면 PC 에 USB 로 연결한 채 `adb logcat -s took` 출력이나 화면 사진을 보내 주면 원인을 찾는다.

## 3. 조명에 따른 입술 색 (20분)
같은 립 색이 매장 조명에서 얼마나 달라 보이는지 본다. 결과에 따라 2단계에서 링 조명(하드웨어)과 카메라 화이트밸런스 고정 중 무엇을 할지 정한다.

1. 거울에서 다이얼로 **빨강 계열 한 칸**을 고른다 (모든 사진에서 같은 칸)
2. 아래 조명마다 거울 화면을 **같은 자리·같은 거리**에서 휴대폰으로 찍는다
3. 같은 자리에 **흰 종이**를 한 장 들고 같이 찍으면 비교가 쉽다

| 조명 | 사진 파일 | 입술 색이 어떻게 보이나 (예: 주황빛, 어두움) |
|---|---|---|
| 매장과 비슷한 천장 조명 | | |
| 창가 자연광 | | |
| 어두운 곳 | | |
| (있으면) 링 조명 | | |

→ 사진을 보내 주면 색 차이를 재서 보정이 필요한지 판단한다.

## 4. 챗봇 (결정됨: 외부 AI 없이 규칙 챗봇 보강)
2026-11-20 결정: API(유료)를 붙이지 않는다. Claude Max 구독은 프로그램에서 쓸 수 없고, 시연에는 규칙 챗봇으로 충분하다.
대신 손님이 할 법한 새 말 167개로 빈틈을 찾아 사전·규칙을 채웠다: 못 알아듣는 말 **70개 → 4개**, 평가 **215/217 (99.1%)**, 지어낸 답 0건 (`test/eval/README.md` '손님 말 2차').

확인할 것: 키오스크에서 실제로 몇 마디 해 보고 못 알아듣는 말을 적어 주면 같은 방식으로 채운다.

| 손님이 한 말 | 챗봇 답이 이상했던 점 |
|---|---|
| | |

> 발표할 땐 "자체 개발한 규칙 기반 AI 챗봇, 생성형 AI로 손님 말을 만들어 다듬었다"고 설명한다 (실시간 GPT 연결이라고 하지 않는다).
