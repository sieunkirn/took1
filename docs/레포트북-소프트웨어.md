## 1쪽 — 소프트웨어 개요

### 한 문장 요약
took(툭)은 **거울 앞에 선 손님의 입술을 카메라로 찾아, 실제 판매 중인 립 색을 실시간으로 입혀 보여 주고, 터치 몇 번으로 어울리는 제품을 추천하는** 스마트미러 소프트웨어다.

### 구성
| 기술 갈래 | 하는 일 | 핵심 기술 |
|---|---|---|
| ① 보는 기술 | 얼굴·입술 위치를 찾는다 | 얼굴 랜드마크 인식(AI 모델) |
| ② 칠하는 기술 | 입술에 립 색을 자연스럽게 입힌다 | Lab 색 공간, 마스크·페더링, 조명 보정 |
| ③ 비교하는 기술 | 색이 얼마나 비슷한지 잰다 | CIEDE2000 색차 공식 |
| ④ 알아보는 기술 | 손님의 피부 톤과 손에 든 제품을 알아본다 | 피부 톤 측정, NFC |
| ⑤ 추천하는 기술 | 질문 3개로 어울리는 제품을 고른다 | 플로팅 퀵 추천 |

`[그림] 노트북 + 세로 모니터(거울) + 웹캠 + NFC 리더기 연결도, 화면 흐름(거울 → 플로팅 추천 → 추천 시트)`

### 설계 원칙
1. **기기 안에서만 계산한다** — 모든 계산은 매장 노트북의 브라우저(Chrome)에서 일어난다. 별도 설치가 없고, 카메라 영상은 밖으로 보내지 않는다.
2. **지어내지 않는다** — 추천은 실제로 수집한 제품 데이터 안에서만 고른다. 데이터에 없는 정보(보습력·지속 시간 등)는 만들어 내지 않는다.
3. **실제·추정·시연을 구분한다**

| 실제로 동작 | 추정값 | 시연용 |
|---|---|---|
| 입술 인식·색 입히기, 색 비교·추천, 피부 톤 측정, NFC 인식, 퀵 추천, 터치 보정 | 호수 색(사진에서 추출), 제형·색 계열 분류 | 매장 위치·재고 |

### 운영을 받쳐 주는 기술
- **웹앱**: HTML·CSS·JavaScript로 만들어 브라우저만 있으면 실행된다. 화면은 세로 900×1440(5:8) 하나를 기준으로 그리고 어떤 모니터에서도 비율을 유지한다.
- **터치 보정**: 거울 위 터치 필름은 화면과 조금씩 어긋난다. 십자 표시 5개를 차례로 누르게 해서 "누른 곳 ↔ 눌렀어야 할 곳"의 차이로 **아핀 변환**(밀림·늘어남·기울어짐을 한 번에 고치는 식)을 **최소제곱법**으로 계산해 모든 터치에 적용한다.
- **자동 초기화**: 90초 동안 조작이 없으면 10초를 센 뒤 고른 색·답변·언어 설정을 모두 지운다. 회원 정보나 사진은 저장하지 않는다.

## 2쪽 — 보고, 칠하는 기술

### ① 얼굴 랜드마크 인식
구글이 공개한 **MediaPipe Face Landmarker**로 얼굴에 **478개의 점**을 찍고, 그중 입술 바깥선·안쪽선의 점만 쓴다. 수많은 얼굴 사진으로 학습한 딥러닝 모델이라, 조명·피부색·립 색이 달라도 입술을 찾는다.

- **떨림 줄이기**: 매 장면 점이 조금씩 흔들리므로 직전 위치와 섞어 부드럽게 하되, 입이 크게 움직이면(입 너비의 3% 이상) 섞지 않고 바로 따라가 색이 뒤처지지 않게 했다.
- **속도**: 가능하면 GPU로, 안 되면 CPU로 자동 전환해 1초에 수십 번 다시 찾는다.
- **한 명만**: 거울 앞 손님 한 명의 얼굴만 추적한다.

### ② 진짜 바른 것처럼 칠하기
입술 위에 색 도형을 덮으면 스티커처럼 보인다. 실제 립은 주름·그림자·빛 반사가 비쳐 보이기 때문이다.

| 기술 | 원리 | 효과 |
|---|---|---|
| 마스크·페더링 | 입술 점을 이어 만든 틀 안만 칠하고, 입을 벌리면 안쪽(치아·혀)은 비운다. 가장자리는 입 크기에 맞춰 살짝 흐리게 | 경계가 칼로 자른 듯하지 않고 자연스럽게 번짐 |
| Lab 색 공간 | 색을 밝기(L)와 색 성분(a, b)으로 나눠, **원래 입술의 밝기 변화(L)는 살리고 a·b만** 립 색으로 바꿈 | 주름·입체감이 남은 채 색만 바뀜 |
| 조명 보정 | 입술 옆 피부의 밝기·색으로 현재 조명을 추정해 칠할 색을 조금 조정(폭 제한) | 매장 조명에서도 실제 바른 색처럼 보임 |

**질감 표현** — 같은 색도 질감에 따라 빛을 받는 방식이 다르다.
| 매트 | 글로시 | 시어 | 쉬머 |
|---|---|---|---|
| 반사 없음, 명암 대비 낮게 | 원래 밝은 부분을 더 밝게 | 색을 옅게 덮어 입술이 비침 | 흩어진 작은 점을 밝게 |

`[그림] 원본 입술 / 마스크 / 색 입힌 결과 비교, 질감 4종`

## 3쪽 — 비교하는 기술과 데이터

### ③ CIEDE2000 — 사람 눈 기준의 색 차이
"비슷한 색"을 찾으려면 색 차이를 숫자로 재야 하지만, RGB 숫자끼리의 차이는 사람이 느끼는 차이와 맞지 않는다. 사람 눈은 색 계열마다 민감도가 다르기 때문이다.
**CIEDE2000**은 국제조명위원회(CIE)가 사람의 색 구별 실험을 바탕으로 만든 색차 공식으로, 화장품·인쇄 업계의 색 검사 표준이다. 결과값을 **ΔE**라 한다.

| ΔE | 사람이 느끼는 정도 |
|---|---|
| 1 이하 | 거의 구별 못 함 |
| 2 ~ 3 | 나란히 두면 겨우 알아챔 |
| 5 이상 | 다른 색으로 보임 |

took은 목표 색과 모든 제품 호수의 ΔE를 계산해 **작은 순서대로** 추천하고, 화면에는 `유사도 = 100 − 2 × ΔE` (%)로 보여 준다. 무작위 요소가 없어 같은 색이면 언제나 같은 결과가 나온다. 제품당 가장 가까운 호수 하나만 보여 준다.

### 데이터 수집
| 단계 | 방법 |
|---|---|
| 수집 | 웹 크롤링으로 올리브영 판매 페이지에서 제품 이름·가격·사진·호수·호수별 바코드를 모음 (립 272개, 호수 2,033개) |
| 색 추출 | 호수별 색상 칩 사진에서 흰 배경을 버리고, 남은 픽셀을 밝기순으로 세워 **어두운 쪽(그림자)·밝은 쪽(반사광) 30%씩 잘라 낸 가운데 40%의 평균** → 그림자·반사에 휘둘리지 않는 대표색 |
| 검수 | 판정이 애매한 호수(거의 회색·흰색 사진 등)는 검수 화면에서 사람이 넣고 뺌 |
| 사용 | 호수 정보가 확인된 **199개 제품 · 호수 2,002개**를 추천에 사용 |

- 사진에서 뽑은 색은 **추정값**임을 데이터에 기록한다(`color_source`).
- 가격대는 6,500원 ~ 52,000원, 가운데값 16,000원이다(추천 대상 199개 제품 기준).

`[그림] 색 칩 사진 → 픽셀 정렬 → 가운데 40% 평균 과정`

## 4쪽 — 알아보는 기술: 피부 톤 측정과 NFC

### 피부 톤 측정 — 카메라로 퍼스널 컬러 추정
얼굴 랜드마크로 찾은 세 곳의 색을 잰다.

| 재는 곳 | 쓰는 이유 |
|---|---|
| 볼·이마 **피부** | 피부 바탕색(노란 기 / 붉은 기)과 밝기 |
| **눈 흰자** | 원래 흰색에 가까운 기준점 → 조명 색을 되돌리는 **화이트 밸런스** 보정 |
| **눈썹** | 피부와 눈썹의 밝기 차이(대비) → 깊고 선명한 톤인지 판단 |

1. **여러 장면의 중앙값**: 순간적인 빛 변화에 흔들리지 않도록 15장면을 재서 중앙값을 쓴다.
2. **조명 되돌리기**: 눈 흰자가 피부보다 밝고 보정한 피부색이 실제 피부색 범위에 들 때만 흰자로 조명을 보정한다. 관리자가 흰 종이로 카메라 색을 보정해 두었으면 그 값을 먼저 쓴다.
3. **두 축으로 분류**: 보정한 피부의 Lab 색상각이 기준(56°) 이상이면 **웜**, 미만이면 **쿨**. 피부 밝기와 눈썹 대비로 **밝은 톤 / 깊은 톤**. 두 축의 조합으로 **봄 웜 · 여름 쿨 · 가을 웜 · 겨울 쿨** 중 하나를 고른다. 경계에 가까우면 두 번째 후보도 함께 기록한다.
4. **어울리는 립 색**: 계절마다 립 목표색(색상각·밝기·채도)을 정해 두고, 체험용 예시 색 22가지 중 목표색에 가장 가까운 색을 고른다. 실제 제품은 이 색을 기준으로 ③의 ΔE 계산으로 다시 찾는다(예시 색 자체는 판매 제품이 아니다).

**측정 도우미** — 손님이 측정 요령을 몰라도 되도록, ① 할 일 세 줄(얼굴 맞추기 · 정면 보기 · 밝은 곳) ② 얼굴 인식 여부 실시간 표시 ③ 얼굴을 찾으면 **3초를 센 뒤 자동 측정**한다. 카메라가 없거나 얼굴을 못 찾으면 이유를 알려 주고 직접 고르는 길로 돌려보낸다.

### NFC — 손에 든 제품을 바로 입술에
**NFC**는 몇 cm 안에서만 통신하는 무선 기술(교통카드와 같은 방식)이다. 제품에 붙인 배터리 없는 스티커가 리더기의 전파로 **고유 번호(UID)** 를 돌려준다.
- 리더기는 **키보드인 척** 연결돼 드라이버 없이 브라우저로 번호를 받는다.
- 사람이 친 글자와는 **글자 사이 간격**으로 구별한다. 기계만 낼 수 있는 빠른 입력만 태그로 인정한다.
- 태그하는 순간 그 제품 색을 입술에 바르고, 화면 아래에 실제 호수 줄을 띄워 눌러 가며 다른 호수를 입어 볼 수 있다.

`[그림] 측정 도우미 화면, NFC 태그 시트`

## 5쪽 — 추천하는 기술 ①: 퀵 추천의 설계 근거

### 대화형 챗봇에서 선택형으로
처음에는 화면 키보드로 묻는 **규칙 기반 챗봇**이었다(생성형 AI가 아니라 정해진 규칙으로만 답해 없는 제품·가격을 지어내지 않는 방식). 그러나 키오스크에서는 ① 서서 화면 키보드로 문장을 쓰기 어렵고 ② 무엇을 물어야 할지 모르는 손님은 첫 문장부터 막히며 ③ 긴 답이 거울 속 입술을 가렸다. 그래서 **거울 위 플로팅 버튼 하나로, 터치 몇 번에 끝나는 선택형 추천**으로 바꿨다. 지어내지 않는다는 원칙은 그대로 유지했다.

### 왜 질문 3개인가
- 선택지가 늘수록 결정 시간이 길어지고(**Hick–Hyman 법칙**), 너무 많으면 오히려 고르지 못하고 떠난다(**선택 과부하**, Iyengar & Lepper, 2000). 짧게 머무는 키오스크에서는 질문 하나하나가 이탈 지점이다.
- 립 색을 정하는 정보를 **상황 · 사람 · 취향** 세 축으로 나누면 서로 겹치지 않으면서 결과 색을 각각 다른 방향으로 바꾼다.

| 순서 | 질문 | 선택지 | 답하기 | 놓은 이유 |
|---|---|---|---|---|
| ① | 어떤 날 바를 립? (상황) | 데일리 · 데이트 · 면접 · 하객·행사 | 매우 쉬움 | 첫 질문이 쉬워야 이어진다. 메이크업의 기본인 TPO |
| ② | 퍼스널 컬러? (사람) | 봄 웜 · 여름 쿨 · 가을 웜 · 겨울 쿨 / 모르면 측정 | 어려움 | 결과 색을 가장 크게 좌우. 흐름을 탄 뒤 묻고, 모르면 측정 길 제공 |
| ③ | 어떤 분위기? (취향) | 화사하게 · 차분하게 · 자연스럽게 · 또렷하게 | 쉬움 | 앞의 두 답으로 만든 색을 **견본으로 미리 보여 주며** 고르게 함 |

- **선택지는 4개, 2×2 격자**: 한눈에 들어오고 버튼을 손가락 크기(약 260×104px)로 만들 수 있다(**Fitts의 법칙**: 목표가 클수록 빠르고 정확하게 누른다). 하객과 행사는 '격식 있되 튀지 않게'라는 같은 방향이라 합쳤다. 상황에는 선 아이콘을, 톤·분위기에는 색 견본을 붙여 글을 다 읽지 않아도 고를 수 있다.

- **사용성 장치**: 창은 얼굴 아래에만 떠 고르는 동안에도 입술이 보이고, 1/3 → 3/3 진행 표시, 언제든 닫는 X 버튼, 망설이면 "고르기 어려우세요?" 같은 말풍선 안내를 둔다.

### 왜 가격·고민은 나중에 묻나
정보를 필요할 때 단계적으로 여는 **점진적 공개** 원칙을 따랐다. 가격·건조함·지속력은 결과를 본 뒤에야 의식되는 불만인 경우가 많다. 먼저 결과를 보여 주고 아쉬운 손님에게만 "어떤 점이 아쉬우세요?"를 물으면, 만족한 손님은 **3번의 터치로 끝난다.**

`[그림] 질문 ①~③ 화면과 흐름도`

## 6쪽 — 추천하는 기술 ②: 동작 원리와 한계

### 답이 추천으로 바뀌는 과정
```
② 톤의 기본 립 색 ──▶ ①·③ 답만큼 밝기·채도 조정 ──▶ 그 색을 입술에 바로 입힘
                                              └──▶ CIEDE2000으로 가까운 실제 제품 + 제형 조건 ──▶ 추천 시트
```

| ① 상황 | 밝기/채도 | 제형 | ③ 분위기 | 밝기/채도 | 제형 |
|---|---|---|---|---|---|
| 데일리 | +4 / −8 | — | 화사하게 | +5 / +10 | 글로시 |
| 데이트 | +3 / +6 | 글로시 | 차분하게 | −5 / −10 | 매트·벨벳 |
| 면접 | 0 / −15 | 매트·벨벳 | 자연스럽게 | +3 / −18 | — |
| 하객·행사 | −2 / +4 | — | 또렷하게 | −3 / +18 | — |

- 제형은 **분위기가 있으면 분위기를, 없으면 상황을** 따른다(손님이 직접 원한 것이 우선).
- 결과는 거울의 추천 시트로 열리고 **1위 제품을 입술에 바로 입힌다.** 시트 위에는 "‘면접 · 봄 웜 · 자연스럽게’ 맞춤 추천 립이에요"처럼 **고른 답을 되돌려 줘** 왜 이 제품인지 알 수 있게 한다.

### 마음에 안 들 때 — 보완 질문
| 아쉬운 점 | 바뀌는 조건 |
|---|---|
| 가격 | 드래그 바로 고른 금액 **이하** 제품만 |
| 건조해요 | 글로시 제형만 |
| 지속력 | 매트·벨벳 제형만 |
| 발색 | 지금 색을 더 진하고 선명하게 (밝기 −7 / 채도 +12) |
| 처음부터 | 질문 ①로 |

- 조건은 **쌓인다**("9,000원 이하로 · 촉촉한 제형으로 다시 골랐어요").
- **가격 드래그 바**: 범위 = DB의 실제 가격대(6,500 ~ 52,000원, 서버가 계산), 처음 위치 = **가운데값 16,000원**. 평균과 달리 소수의 비싼 제품에 끌려가지 않아, 바를 안 움직여도 절반가량(199개 중 105개)이 남는다. 가격대 밖은 고를 수 없어 '결과 없음'을 막는다.

### 한계와 검증 계획
- **인식 환경**: 강한 색 조명, 옆모습·가린 입에서는 부정확할 수 있다. 호수 색은 사진에서 뽑은 추정값이다.
- **설계 가설**: 위 조정량은 메이크업 관습에서 정한 초기값이고, 건조·지속력은 보습·지속 데이터가 없어 **제형으로만** 판단한다.
- **검증 지표(제안)**: 플로팅 버튼 → 추천 시트 도달 비율, 보완 질문 사용 비율·가장 많은 불만, "추천 1위가 원한 느낌과 맞았는가" 사용자 응답.

## 7쪽 — 사업적 요구사항

took은 손님 · 매장 · 브랜드 세 이해관계자의 요구를 함께 풀어야 팔린다. (구현 = 동작함, 시연 = 가짜 데이터, 향후 = 아직 없음)

| 대상 | 요구 | 대응 기능 | 상태 |
|---|---|---|---|
| 손님 | 바르지 않고 위생적으로 여러 색을 체험 | 실시간 가상 립 메이크업, NFC로 든 제품 바로 체험 | 구현 |
| 손님 | 짧은 시간에 결정, 뷰티 지식 없이도 사용 | 질문 3개 퀵 추천, 모르면 톤 측정 도우미 | 구현 |
| 손님 | 개인정보 걱정 없음 | 영상 미전송, 90초 무조작 시 자동 초기화, 회원·사진 미저장 | 구현 |
| 손님 | 외국인 손님도 사용 | 한국어 / 영어 전환 | 구현 |
| 매장 | 테스터 소모·위생 관리 부담 감소 | 가상 체험으로 실물 테스터 사용을 줄임 | 구현 (효과는 검증 필요) |
| 매장 | 직원 응대 부담 감소, 상담 품질 균일 | 규칙대로 같은 답을 내는 추천(지어내지 않음) | 구현 |
| 매장 | 쉬운 설치·운영 | 노트북 + 모니터 + 웹캠 + NFC 리더(USB), 설치 프로그램 없이 Chrome만 | 구현 |
| 매장 | 추천 제품이 실제로 매장에 있는지 | 매장 재고 연동 | 시연 (가짜 재고) |
| 브랜드 | 정확한 호수 색 표현 | 호수별 색 추출·검수 데이터, CIEDE2000 비교 | 구현 (색은 추정값) |
| 브랜드 | 신제품·캠페인 노출 | 대기 화면·말풍선 영역의 캠페인 노출 | 향후 |
| 브랜드 | 손님 선호 파악 | 익명 집계 리포트(많이 고른 상황·톤·분위기, 많이 발라 본 색) | 향후 (집계 기능 없음) |

**비기능 요구**
- 실시간성: 입술을 1초에 수십 번 다시 찾아 색이 손님 움직임을 따라가야 한다.
- 오프라인 동작: 매장 인터넷이 끊겨도 기기 안의 정적 버전으로 추천까지 돌아간다.
- 데이터 갱신: 신제품·가격 변경을 크롤링 → 색 추출 → 사람 검수 → 앱 반영 순서로 주기적으로 업데이트한다.
- 신뢰성: 추천 순위는 색차 계산으로만 정하고, 광고·제휴로 순위를 바꾸지 않는다.

## 8쪽 — 수익 구조

기본 수익은 매장의 월 구독료이고, 브랜드 캠페인과 익명 데이터 리포트로 키운다. 금액은 파일럿 지표로 정하므로 빈칸으로 둔다(초안).

| 매출원 | 누가 내나 | 내용 | 시점 | 금액 |
|---|---|---|---|---|
| ① 소프트웨어 구독 | 매장 | 기기 1대당 월 이용료 (소프트웨어, 제품·호수 데이터 업데이트, 원격 지원) | 1단계 | [ 파일럿 후 ] |
| ② 설치 패키지 | 매장 | 거울형 모니터 + 노트북 + 웹캠 + NFC 리더 설치·터치 보정. 판매 또는 임대 | 1단계 | [ 견적 ] |
| ③ 브랜드 캠페인 | 브랜드사 | 신제품 기간 대기 화면·말풍선 노출, NFC 태그 지원. "광고" 표시, 추천 순위 영향 없음 | 2단계 | [ 파일럿 후 ] |
| ④ 익명 데이터 리포트 | 브랜드사·MD | 개인을 알 수 없는 집계: 상황·톤·분위기 선택 비율, 많이 발라 본 색, 불만 순위 | 3단계 | [ 파일럿 후 ] |

**비용 구조**
- 하드웨어(모니터·노트북·웹캠·NFC 리더·스티커), 설치·유지보수(현장 설치, 터치 보정, 원격 지원).
- 데이터 운영: 신제품마다 크롤링·색 추출·사람 검수 반복. 서버 비용은 계산이 기기 안에서 일어나 작다.

**단계별 계획**
| 단계 | 하는 일 | 넘어가는 조건 |
|---|---|---|
| 1. 파일럿 | 1~2개 매장에 무상 또는 저가로 설치, 사용 지표 수집 | 체험 수 · 추천 시트 도달 비율 · 매장 만족도 확인 |
| 2. 구독 전환 | 구독료 책정, 설치 매장 확대, 브랜드 캠페인 시작 | 매장 재계약률, 캠페인 문의 |
| 3. 데이터 사업 | 익명 집계 기능 개발, 리포트 판매 | 개인정보 검토 완료, 리포트 수요 확인 |

전제·위험: 추천 순위를 돈으로 바꾸지 않고 집계는 개인을 알 수 없게 한다는 원칙을 계약에 적는다. 재고 연동이 없으면 "추천했는데 매장에 없음"이 생기므로 2단계 전에 검토한다.
